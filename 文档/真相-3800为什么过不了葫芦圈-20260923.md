# 真相：3500 / 3800 / 4000 三个版本**都过不了**葫芦圈

日期：2026-09-23
结论来源：**逐字节 diff**（`Compare-Object`），不是推测。

---

## 一、先说结论

**"3500 能过葫芦圈"这个记忆是错的。**

3500、3800、4000 这一串版本的**葫芦圈出圈代码压根没有编译进固件**：

```
#define USE_GOURD_EXIT       0      ← 整个出圈状态机被 #if 掉
#define USE_GOURD_IG_GYRO    0      ← 连"有没有进圈"都判断不了
```

所以车进了葫芦圈以后，**没有任何逻辑会让它右转出来**，
它只会顺着线一直跑 —— 也就是用户描述的：

> **"会一直绕着一个圈走"**

## 三、那到底是哪一版能出圈？

能出圈的只可能是**把开关打开的版本**，即 3600 / 3700 / **3900**：

| 版本 | `USE_GOURD_EXIT` | `USE_GOURD_IG_GYRO` | 葫芦圈 | 直角弯 |
|---|---|---|---|---|
| 3500 | 0 | 0 | ✗ 一直转圈 | ✓ 正常 |
| 3800 | 0 | 0 | ✗ 一直转圈 | ✓ 正常 |
| 3900 | **1** | **1** | ✓ **能出圈** | ✗ **转向反了** |
| 4000 | 0 | 0 | ✗ 一直转圈 | ✓ 正常 |
| **4100** | **1** | **1** | 目标：能出圈 | 待观察（有已知风险） |

3900 的两个现象是**同一个原因**的两面：
出圈判据 `11000000`（只有最左两路亮）
**在右直角弯的出口也会出现**（车左转时线滑向右侧），
于是直角弯被误判成"葫芦出口" → 触发 90° 硬右转 → 转向反了。

> 详见 `文档\失败复盘-出圈判据打坏直角弯-20260923.md`

**结论：出圈能力和直角弯误触发，都是 `USE_GOURD_EXIT=1` 带来的。
要"能出圈"就必须接受这个风险；要"没有风险"就只能一直转圈。
唯一的出路是把出圈判据换成不会误伤的 —— 也就是里程。**

## 四、由此得出的正确路线

用户方案（原话）：

> "利用编码器计数，计算小车跑了多少距离，最后到出葫芦圈的时候强制右转"

为什么里程是**唯一**不会误伤的判据：

| 判据 | 会不会在右直角弯误触发 | 原因 |
|---|---|---|
| 图案 `11000000` | **会** | 右直角弯出口图案完全一样 |
| 圈内持续丢线 | **会** | `ge_in_gourd` 印记没清干净时就误触发 |
| **按里程** | **不会** | 是**物理量**，与"看到了什么图案"完全无关 |

### 分两步走

**第 1 步（当前，FW:0923-4100）—— 恢复出圈能力 + 采集里程数据**

```
USE_GOURD_EXIT        1     ← 恢复
USE_GOURD_IG_GYRO     1     ← 恢复
GOURD_EXIT_USE_PATTERN 1    ← 用能出圈的判据先把圈过去
GOURD_EXIT_ON_LOST    0     ← 关掉（它是误触发直角弯的嫌疑之一）
USE_GOURD_EXIT_ODOM   0     ← 里程判据代码已编译在内，但先关闭
```

新增遥测 `ODE=` = **从进圈那一刻起算**的净位移(mm)。
出圈事件行也会打印：

```
GOURD-EXIT: trig=1 -> turn RIGHT   ODE=xxxxmm  (left2 lit, yaw closed loop)
```

**把那个 `xxxx` 记下来 = 葫芦圈"进圈→出口"的真实里程。**

**第 2 步（FW:0923-4200）—— 换成纯里程触发**

```
GOURD_EXIT_ODOM_MM    <上一步实测的 xxxx，建议再减 50~100mm 留余量>
GOURD_EXIT_USE_PATTERN 0    ← 关掉误触发源
USE_GOURD_EXIT_ODOM   1     ← 打开
```

从此出圈由**里程**决定 → **右直角弯不可能再被误伤**。

## 五、为什么里程要以"进圈那一刻"为 0 点

不是从发车算起。原因：

* 发车位置前后摆 10cm，从发车算的里程就整体偏 100mm → 每次都要重标；
* 以"进圈那一刻"（`ge_in_gourd` 0→1 边沿）为 0 点 →**与从哪儿发车无关**，
  换发车位置、换赛道摆放都不用重标。

实现：进圈边沿处记 `ge_odom_entry = odom_distance_mm();`，
之后判 `odom_distance_mm() - ge_odom_entry >= GOURD_EXIT_ODOM_MM`。

## 五点五、实车结果：图案判据已被证伪（FW:0923-4100，2026-09-23）

### 实测结果

| 项目 | 结果 |
|---|---|
| 葫芦圈 | **仍然出不去** ❌ |
| 右直角弯 | **又被误触发** ❌ |

### 这两件事合起来说明了什么

图案判据开着、闸门也开着，葫芦圈**却仍然出不去** ——
说明 `11000000` 在葫芦圈里命中的**不是出口，而是中途某个拐点**。

后果是致命的，因为 `GOURD_EXIT_ONE_SHOT 1`：

```
车在葫芦圈【中途拐点】命中图案
   → 转一次
   → ge_fired = 1  【上锁】
   → 到真正的出口时锁还没解 → 再也不转了
```

而且那一次中途的硬右转本身就把蛇行路线打乱了 ——
这正是最初那句"绕圈的顺序也变了，差点都没过去"的真正原因。

### 直角弯为什么连闸门都挡不住

闸门 `GOURD_EXIT_REQUIRE_ENTRY` 的前提是 `ge_in_gourd = 1`。
而进圈判据（`USE_GOURD_IG_GYRO`）是"10 拍内 |GZ| 累计 ≥ 1000 且车在跑"。

> **一个 90° 直角弯本身就是"持续大角速度"** ——
> 所以车一进直角弯，闸门立刻被打开。

**出圈能力和直角弯误触发，是同一个判据的两个后果。**

### 结论

| 判据 | 状态 |
|---|---|
| ① 图案 `11000000` | ☠ **彻底放弃** —— 直角弯和圈内拐点都误触发 |
| ② 圈内持续丢线 | ⚠ 依赖 `ge_in_gourd`，同样被直角弯打开 → 不可靠 |
| ③ **按里程** | ✅ **唯一出路**（且见下面这条有利性质） |

### ★ 里程判据有一个意外的好性质

里程判据要求 `ge_in_gourd` **连续保持**约 2000mm。
而直角弯里印记 **200ms 后就自动清了**
（线变回普通线 20 拍 → `GOURD_ENTRY_CLEAR_FRAMES`）。

> **直角弯根本撑不到 2000mm。**
> 只有真正的葫芦圈（蛇行持续转弯）才撑得住。

**所以里程判据对直角弯是天生免疫的 —— 连 `ge_in_gourd` 偶尔乱跳都不怕。**

### 里程数怎么测（不需要任何出圈逻辑能工作）

葫芦圈里车只会打转，**永远到不了出口**，所以不能靠"开到出口"来测。
改用**手推标定**（FW:0923-4200 为此加了 `O` / `Z` 两条串口命令）：

```
1. 把车放在葫芦圈【入口】，车轮贴地
2. 串口发 Z          → OK ODOM RESET (OD=0 PATH=0)
3. 用手把车沿着【预定的蛇行走线】推到"该开始右转 90°"的那个点
4. 串口发 O          → ODOM NOW: OD=xxxxmm PATH=yyyymm L=.. R=..
5. 抄下 xxxx
```

* `Z` 可以在任意位置重新清零 → **可以反复测，不用断电**
* **重复 3 次**，若三次差值在 ±50mm 内，说明可信
* 顺手看 `L=` 和 `R=`：两者差得太多说明推的时候有拖拽，数不可信
* ⚠️ 推的时候让轮子**滚动**，不要拖着走

## 六、里程计本身的标定（可选，不影响出圈能否成功）
`ODOM_UM_PER_COUNT = 491`（= π × 66mm × 1000 / 422 计数）。
若轮径不是实测的 66mm，`ODE` 会整体成比例偏差。

**标定方法**：直线上量好 **2.0 m**，把车放在起点，
按暂停 → 读 `ODOM STOP: OD=?mm`。应该是 2000 左右。
若不是，把 `ODOM_UM_PER_COUNT` 按 `491 × (2000 ÷ 实测值)` 修正。

> ✅ **这一步不做，出圈照样能成功。**
> 因为"测量"和"触发"用的是**同一个里程计**：
> 设真实系数错了 k 倍，测出来的阈值也跟着错 k 倍，
> 触发时再乘同一个 k → **误差自己抵消**。
> 标定只影响 `OD=` 显示的数值是不是真毫米，不影响能不能出圈。

## 七、结局（2026-09-23）：里程触发 **403mm** 定稿

### 实测数据

> **葫芦圈"进圈 → 出口"净位移 = 403mm**

来源：`FW:0923-4600`（里程流模式，10Hz 只发 `OD=xxxxmm`）实车读数。

> 📌 **更正上面第五节的一个估计值**：那里写的"约 2000mm"当时只是占位猜测。
> 实测是 **403mm**。免疫性结论**依然成立** ——
> 直角弯的印记只能撑约 200ms（≈60mm），**远不到 403mm**。

### 定稿版本 `FW:0923-4800`

**基底 = `FW:0923-4200`**（用户确认"这个版本没问题了"的那一版，直角弯正常），
在它之上**只叠加一处功能改动**：

```
USE_GOURD_EXIT_ODOM        0 -> 1       启用里程触发
GOURD_EXIT_ODOM_MM      2500 -> 403     实测值
GOURD_EXIT_ODOM_FROM_START  新增 = 0    从"进圈那一刻"起算
FW_TAG          "0923-4200" -> "0923-4800"
```

其余（控制逻辑 / 遥测 / 按键）**全部 4200 原样**。
（4300/4400/4500/4600/4700 都是为了测这个数搭的脚手架，已清除。）

### 为什么基准选"从进圈起算"

| 基准 | 后果 |
|---|---|
| **从进圈起算**（默认 `FROM_START 0`）| 与"车从哪儿发车"**完全无关**；对右直角弯**天生免疫** |
| 从起步起算（`FROM_START 1`）| 车只要跑够 403mm 就转，**与赛道位置无关** —— 不是从葫芦圈入口发车就会乱撞 |

**"完全没转"时的第一招**：把 `GOURD_EXIT_ODOM_FROM_START` 改成 1 试一次
（那说明 403 是从起点线量的，不是从葫芦圈入口量的）。

### 同一天还确认的几条工程事实

* **`LED1 = PC13`**（`main.h:60`）。全工程只有 `CAR_EMERGENCY`（150ms 快闪）
  和 `CAR_STOPPED`（250ms 慢闪）会让 LED1 闪，两处都在 `enter()` 里**无条件**调用 `print_odom()`。
  ⇒ **"PC13 在闪" 等价于 "`print_odom` 执行过"** —— 一个很有用的诊断等式。
* **`speed_update()` 全工程只有 `telemetry_report()` 调用它。**
  任何"静默 / 关遥测"的改动，判断必须放在 `speed_update()` **之后**，
  否则测速冻结 → `GOURD_IG_MIN_RPM`（"车确实在跑"）失效。
* **往字符串字面量里加中文会触发 ARMCC `#870-D`**（源文件 UTF-8，ARMCC 按 GBK
  双字节规则扫）。**字符串字面量一律用英文**；注释里中文没问题。
* **里程流模式**（10Hz 只发 `OD=xxxxmm`）是很有效的**串口链路体检**手段 ——
  连它都看不到，问题就一定在链路上（TX 是否接 PA9 / 共地 / 端口 / 波特率），
  与固件无关。
* **两个 USB 同时插（ST-Link + USB-TTL）会因地环路把串口搞死** —— 跑车前必须拔 ST-Link。
