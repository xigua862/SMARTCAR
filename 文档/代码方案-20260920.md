## 三、功能清单（做完这辆车就齐了）

### A. 启动与人机（全新）
- A1 上电 → `IDLE`：三灯灭、电机停、蜂鸣器不响（防上电乱响，硬件 10k 下拉已做）
- A2 按启动键 → **3s 读秒**：LED1→LED2→LED3 逐个亮（各 1s）+ 每亮一下蜂鸣器"哔"一声
- A3 读秒完 → `RUN`：LED3 常亮 = 循迹中
- A4 **停车后可再按按键重新读秒发车**（比赛要发 2 次）
- A5 状态指示：丢线 → LED2 闪 + 短鸣；到终点 → 三灯闪 + 长鸣 2 声
- A6 长按按键 1s = **急停**（调车时用，比赛不碰车）

### B. 循迹控制（主体，已有骨架要修）
- B1 8 路加权误差（左负右正，-4…+4）
- B2 PD 差速：`corr = KP·e + KD·Δe`，`左轮 = base+corr / 右轮 = base-corr`（已实测过方向）
- B3 速度自适应：直道快 / 弯道慢（按 |e| 阈值）
- B4 D 项低通滤波（已有，压摆头）
- B5 丢线：先按原方向强修 2 个周期 → 仍丢线就原地转找线 → 转 N 圈找不到就停车（防跑飞）

### C. 赛道元素与终点（全新，本方案的重点）
- C1 **十字**：多路同时触发 → 强制直行不转向（等对称触发再退出）
- C2 **Ω / 圆环**：靠 B5 丢线恢复 + 大误差强修正（先跑通再优化）
- C3 **终点**：识别"斑马线图案" → 急停 + 长鸣（判定参数**要用实测数据定**，见 §四）

### D. 测速与闭环（编码器已装）
- D1 编码器读数（TIM3=左 / TIM4=右，四倍频）
- D2 500ms 窗口 RPM（已有）
- D3 速度闭环（PI）：先开环跑顺，再开闭环（**默认关，跑稳了再开**）
- D4 PWM↔RPM 标定系数（闭环必需，M4 实测两句数据填进去）

### E. 调参与遥测（沿用旧车习惯）
- E1 串口/蓝牙命令：`P <KP>` / `D <KD>` / `S <速度>` / `T <1|2> <pwm>`（单电机架空测）/ `H`（诊断）
- E2 修 **S 指令被自适应覆盖**的坑：改成 `S` 同时定"直道速度"，弯道速度 = 直道 × 比例
- E3 打印行保持旧格式（`IR:xxxxxxxx RPM1=.. RPM2=.. KP=.. KD=.. SP=..`）+ 追加状态字，`tune.ps1` 继续可用
- E4 `H` 指令改语义：打印 **8 路原始电平 + 按键 + 编码器计数**（旧车读霍尔 PA11/12，引脚已退役）

### F. 安全与兜底
- F1 丢线超时停车（已有逻辑，参数复核）
- F2 急停（按键长按）
- F3 所有"可能跑飞"的路径都收口到 `motor_stop()`

## 四、思路（关键设计）

### 4.1 状态机（car_fsm 重写）

```
       上电
        ↓
     [IDLE] ──按键──→ [COUNTDOWN 3s: LED1/2/3 + 哔] ──→ [RUN 循迹]
        ↑                                                    │
        │                                               到终点/丢线超时/急停
        └──────────── 按键重启 ←── [FINISH/STOP] ←───────────┘
```

### 4.2 十字怎么判（不靠猜，靠对称性）
- 8 路全亮/大半亮时，当前权重表 `-4…+4` 的和 **天然 = 0** → 只要"多路同时触发"就**直接强制 e=0（直行）**，不做转向。
- 判据：`active ≥ CROSS_ACTIVE_MIN`（初值 5~6）**连续 2~3 帧**才算十字（防单帧毛刺）。
- 好处：十字处不乱修，出去后传感器恢复少数几路亮 → 自动回到正常循迹。

### 4.3 终点怎么判（本方案唯一"要拿数据定"的地方）
- 难点：**终点斑马线 vs 十字**，两者都是"多路触发"，不能靠一路全亮就停车（第一个十字就会误停）。
- 区分思路（**先用实测数据验证再写**）：
  - 斑马线是**垂直于主线的短线段**（50mm 等间距分布在主线两侧）→ 扫过去的图案是"**断续/边缘先亮**"
  - 十字是**两条线交叉** → 图案是"**中间连续 + 两侧同时**"
  - 再加**里程条件**：编码器/时间跑够一段（终点在赛道最后）→ 双条件同时满足才急停
- ★ **落地办法**：M5 先用 A3 纸打印三种图案（斑马线 / 十字 / 普通线），把车架起来**手推过去**，串口把 8 路原始位图打出来 → 拿到真实图案再定参数。**不拍脑袋写判定。**

### 4.4 参数初值（都在 `app_config.h`，在线可改）

| 参数 | 初值 | 依据 |
|---|---|---|
| KP | **2~3**（kp_x10=20~30） | 前瞻 213mm，几何增益约 ×4.3；旧车 10 |
| KD | **0 起步** → 摆头再试 0.5~1.5 | 旧车 3.0，先纯 P 跑通 |
| 直道速度 | **35~45** | 旧车 SP=40 稳 |
| 弯道速度 | 直道 × 0.7 | 先保守 |
| 控制周期 | 10ms | 已有 |
| 丢线：强修 2 帧 / 转 35 / 上限 150 帧 | 复核 | 旧车经验 |
| 编码器 PPR | **422** | = 11 × 9.6 × **4（TI12 四倍频）**；装好**手转一圈核对** |
| 速度环 Kp/Ki | 0（先关） | M4 标定后填 |

## 五、★要你拍板的 6 件事

1. **8 路模块现在 VCC 接的哪儿？**（5V 还是 3.3V）
   —— 这是**唯一能烧单片机**的点：PA0/PA1/PB0/PB1 不耐 5V。
   如果你接的是 5V：请**先别接模块**，用万用表量一下模块 DO 输出高电平是多少伏（≤3.3V 才敢直连；是 5V 就得改 3.3V 供电或加电平转换）。
2. **终点判定用"图案 + 里程"双条件**（见 4.3），且判定参数**等 M5 实测数据出来再定** —— 同意吗？
3. **3s 读秒保留还是缩短？** 比赛计时从裁判发令开始，读秒会白耗 3s（到点积分不受影响，只影响"同分比时间"）。
   建议：**保留但做成可改参数**（`START_COUNTDOWN_MS`），比赛当天想缩成 1~2s 改一个数就行。
4. **蓝牙定位**：只做调参/看数据，**不做遥控行驶**（规则禁止遥控）——确认。
5. **蜂鸣器频率**：先按板上原来的 **2.7kHz** 试，不响/发闷就改 4kHz（改 `Period` 一个数）——认同这个顺序吗？
6. **丝印 logo**：你的板子上有 "2026 机器车循迹+队伍名" 丝印吗？没有的话我们得想个合规办法（贴标/下一版加印）。
