## 二、需要你处理的 3 个风险（按优先级）

### P0 ★ `G7_TURN_TRIG 12` 必须实测标定
你自己在注释里标了"拍脑袋值，先跑一圈看遥测 `G7=` 读到多少再改"。**这是现在最可能出事的一个数**：数到阈值就硬转，若阈值和真实出口位置对不上，就会在直道上拐出去。
→ **跑一圈，读 `G7=` 在葫芦出口的实际值，把 12 换掉**；再看有没有出现 `G7 HIT but not BRANCH`（出现说明阈值位置不对）。有 `G7_TURN_GATE_BRANCH` 闸门兜着，但**闸门是保险，不是标定的替代品**。

### P0 ★ `CROSS_BUDGET_MAX 4` 是赛道硬编码，尽量改成"实测驱动"
你在注释里已经诚实写了前提（"2 个十字 × 每 2 次"）和失效条件（葫芦夹在两个十字中间会错位）——**这点很好**。但结论是：**这个数是拿赛道描述推出来的，不是量出来的**。
→ 建议：**跑一圈看 `CX=` 实测**（你已经把 CX 打进遥测了 ✓），用实测值填；并把**形状层（`CROSS_NEED_BOTH_ENDS`）放在第一优先**，预算层只当"第 N 次以后的保险"。**换赛道/重摆时必须重算这个数**——把它标在 `app_config.h` 那一行的注释里。

### P1 ★ 缺一处集中的"决策优先级"注释
现在 8 层决策的顺序散在代码各处（而且有**两处 `return`**：G7 硬转、丢线兜底）。9/22 那 10 个提交里已经出现 2 次"编译不过/加了又回退"，正是这类顺序事故的苗头。
→ 建议在 `line_follow.c` 顶部加一段注释，写明**谁覆盖谁**。实测顺序如下（可直接抄）：

```
1. 葫芦"图案分裂"检测            （只记事件，不直接控制）
2. G7 最右一路上升沿计数          （只记事件）
3. G7 硬转 → 直接 return          （闭眼转，忽略传感器；优先级最高）
4. 速度自适应（直道/弯道/丢线）
5. 十字：形状判据 + 预算层 + 事件防抖
6. 直线提速（斜坡）
7. 丢线兜底 → return             （加强修正 / 翻转(默认关) / 原地旋转 / 超时停车）
8. on_cross 强制直行 / wide_long 继续转
9. PD + 低通 + 差速输出
```

⚠️ 顺带一个耦合：**第 3 步会写死 `last_error = 3`**（给退出后的 PD 铺路）——这同时会**污染**下游两处用到 `last_error` 的地方（丢线的 `last_error*2`、葫芦的 `gourd_dir`）。翻转默认关着所以现在影响有限，但**这个耦合值得在注释里标出来**，将来开翻转前先想清楚。
