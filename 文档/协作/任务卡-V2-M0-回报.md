## 一、做了什么（对照卡）

1. **目录**：`Core/App/v2/{drv,mid,ctl,app}` 四子目录建好；
2. **头文件**：22 个（卡写 20，按框架 §② 实际清单落到 22：drv 10 + mid 2 + ctl 5 + app 5），**函数签名冻结、新符号一律 `v2_` 前缀**（不与旧 app 树重名）；
3. **drv 真实现**（其余模块按卡留空壳 + `TODO(M1+)`）：
   - `v2_line_sensor`：8 路（PA0 PA1 PA8 PA15 PB0 PB1 PB12 PB13，权重 -7…+7，白=高）；一拍突发 8 次/间隔 1µs + 多数表决；**误差 = 100·Σ(w·s)/(Σs+1)**（差比和"分母+1"，框架 §④）；DWT 也在这（同旧文件做法）；
   - `v2_motor`：TIM2_CH3=PA2 / CH4=PA3（10kHz、ARR 预装载）+ DIR1/2=PA4/PA5、DIR3/4=PB3/PB4；**反转宏沿用实测定稿值 左=1/右=1**；
   - `v2_encoder`：TIM3/TIM4 读计数，**带符号 16 位差**（回绕安全）；`v2_enc_take_delta()`；
   - `v2_odom`：1kHz 积分，**491 µm/计数**、**绝对值法**（|dL|+|dR|)/2；
   - `v2_imu`：**不重写 I2C**，包旧 `drivers/imu.c`（MPU-6500，WHO=0x70）；主循环 100Hz 刷缓存，ISR 只读缓存；
   - `v2_uart`：RX 256B / TX 512B 环形，**主循环轮询收发**（见第四节偏差②）；
   - `v2_buzzer`：TIM1 时基 **1kHz 更新中断** + CH4（PA11）PWM，兼 1kHz 节拍源；
   - `v2_led` / `v2_key`：照旧搬（PC13/PB14/PB15 高亮；PB9 上拉按下低、30ms 消抖、长按 1s）；
4. **1kHz ISR**：`TIM1_UP_IRQHandler`，顺序 = DWT 起表 → `v2_line_read()` → `v2_odom_tick()` → `v2_buzzer_tick()` → 中/内环 **stub（输出 0）** → 哨兵（>300µs 计 `overlong`）；**无浮点、无 printf、无 I2C**；
5. **主循环**：`v2_app_loop()` = `v2_uart_poll()`（每圈）+ 100Hz（key/IMU/FSM）+ 10Hz CSV；
6. **命令（tune.c）**：`V` 版本 / `T <1|2> <pwm>` 点动 / `Z` 里程清零 / `X` 急停；
7. **Keil 工程**：手工加 4 个 Group（`AppV2/Drv|Mid|Ctl|App`）+ IncludePath 追加 4 个 v2 目录；**未跑 CubeMX**（表内手改，已在工程文件里登记）；
8. **main.c**：旧 `app_init/app_loop` 用 `#if 0` 保留（回退点 = 改回 `#if 1`），改调 `v2_app_init()/v2_app_loop()`。

## 四、两处与卡不一致（都已写进代码注释，等军师裁决）

1. **TIM1 时基**：卡写 `PSC=71, ARR=71` —— 那是 **13.9kHz**，与"1kHz 更新中断"目标矛盾；本实现按 1kHz 意图取 **ARR=999**。
   连带：蜂鸣器变成 **1kHz 方波**（旧板 2.7kHz）；卡里"CCR4 脉冲密度 ≈1.4kHz"在 1kHz 中断下做不到（每拍最多改一次 CCR），M0 只验证"不冲突"，音调 M4 再调。
2. **串口改轮询（卡要求"RX 中断→256B 环"）**：`USART1_IRQHandler` 已被旧 `telemetry.c` 占用，而 M0 不许改旧树代码/编译 → 用**主循环轮询**实现等价行为（RX 256B / TX 512B 环）。
   - 顺带好处：**TX 也非阻塞**（旧版 HAL_UART_Transmit 阻塞几毫秒的隐患一起消掉）；
   - 前提已核实：旧 `telemetry_init()` 不再被调用 → `RXNEIE` 没开 → 旧 ISR 不会抢字节；`PA10` 已在 `v2_uart_init()` 重配为"输入+上拉"（PA10 悬空假命令的旧教训）；
   - M1 删旧树后建议切回中断版（那时向量空出来了）。
