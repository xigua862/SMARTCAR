## 2. 根因（对着代码逐条核过）

代码里有两个"强制直行"的分支，相切点**两个都进不去**：

| 分支 | 条件 | 相切点满足吗 |
|---|---|---|
| ① `on_cross` | 宽图案**两端都贴住**（`CROSS_NEED_BOTH_ENDS`） | ✗ 相切点**只贴一端** |
| ② `wide_long` | 宽图案**持续 > `CROSS_MAX_FRAMES`(6) 拍** | ✗ 只持续 2~6 拍 |

相切点的图案判据是 `wide_one = (tL != tR) && cnt >= CROSS_ACTIVE_MIN`
（`line_follow.c` L341，注释原文就写着"只贴一端 = 分支口/**相切点**"）。

⇒ 两个直行分支都不成立 → 掉进 PD 正常路径 → **按单边大误差继续往同一边转**
→ 顺着圆弧转一圈 ✗

### 顺带一个重要结论（省得再走弯路）

`wide` 的定义本身就含"两端都贴"：
```
wide = (r.active >= CROSS_ACTIVE_MIN) && 两端都贴
```
所以 **`CROSS_ACTIVE_MIN` 和 `CROSS_MAX_FRAMES` 这两个值对葫芦圈完全无效**，
调它们不会有任何变化。唯一正确的杠杆是在相切点给转向发直行。

## 3. 几何依据

4 个圆两两**外切** → 相切点处两个圆**共用一条切线** → 航向连续。
所以正确动作是**直着穿过去**，穿过去以后再让 PD 去抓下一个圆的线。
（原来"加倍往同方向转"必然留在原圆上。）

# ★实测结果（2026-09-24 晚）：**没成功，而且更差了 → 已回退**

固件 `0924-2315` 实跑：`GOURD-TANGENT` 判据成立 **5 次**
（OD=1812 / 2256 / 2623 / 3542 / 4351），但结果**退化成"第 1 个圈就绕圈"**。

## 决定性证据：第 1 次触发（OD=1812）

```
BRANCH #3 IR=11001110 e=-3 -> NOT cross (turn)     ← 原逻辑判定"该转弯"
      IR=11111111                                    ← 8 路全亮 = 厚黑块（不是相切点）
GOURD-TANGENT: straight 6 fr (OD=1812 GW=0)         ← 我的窗口【覆盖】了上面那个判定
      IR=00000111
      IR=00000000                                    ← 直接冲进空白区，连丢 3 拍
      IR=00000000
      IR=00000000
```

## 结论（两条，都很硬）

1. **`IR=11111111`（8 路全亮）不是相切点，是厚黑块/交叉。**
   判据 ②（陀螺翻号）+③（无全灭）**拦不住它** ——
   所以"判定成立"≠"真相切点"，这道门还不够严。

2. **原逻辑在这类图案上判的是 `BRANCH → turn`，而且是对的。**
   我的窗口把它**覆盖成"直行"** → 车冲进空白区。
   ⇒ 不是"原逻辑缺一个直行分支"，而是**我加的直行分支在错误的位置压掉了正确的转向**。

**下一轮日志的用途**：`GOURD-TANGENT` 行会告诉我们"判定成立"到底落在哪些 IR 图案上。
如果每次都是 `11111111`/`11111110` 这种厚黑块 → 说明它根本不是相切点探测器，
真正的相切点判据需要重做（而不是继续调它的输出）。

> ⚠️ 教训（写给以后的自己）：**在"触发时机是否可靠"没被独立验证之前，
> 不要给它加任何"强制动作"** —— 误触发会被动作放大成"冲出去丢线"，
> 比不加更差。应该先只打印、只看，确认位置对了再加动作。
