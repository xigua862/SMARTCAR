# 失败复盘：「出圈转向」为什么会打坏直角弯（2026-09-23）

> 这是这个项目里**我犯的最严重的一次方向性错误**。写下来，避免以后（包括我自己）再犯。

---

## 一、事实

| 版本 | 改动 | 用户实车结果 |
|---|---|---|
| `0923-3500` | 所有葫芦圈功能**关闭** | **"问题最小，葫芦圈绕圈状态都是对的，没啥毛病，但就是出不去"** |
| `0923-3700` | 开了 `USE_GOURD_EXIT` + `USE_GOURD_IG_GYRO` + `GOURD_EXIT_ON_LOST` | **"很烂。直角弯转向都是反的，绕圈的顺序也变了，差点都没过去"** |

对比开关：
```
3500:  USE_GOURD_EXIT=0  USE_GOURD_IG_GYRO=0
3700:  USE_GOURD_EXIT=1  USE_GOURD_IG_GYRO=1  GOURD_EXIT_ON_LOST=1
```

---

## 二、根因（一个我早该想清楚的判断错误）

**出圈判据用的是"只有最左两路亮"（位图 `11000000`）。**

但这**同样出现在左直角弯的出口**：
```
车往左拐 → 线相对车身往右跑 → 最后只剩最左那两路压线
     → 位图 = 11000000     ← 和"葫芦圈出口"一模一样
```

**所以一开 `USE_GOURD_EXIT`，直角弯出口就立刻被当成"葫芦圈出口"** →
执行一个 **90° 硬右转** → **直角弯必然被打坏**（用户说的"转向都是反的"）。

`GOURD_EXIT_ON_LOST` 更糟：圈内任何一次"持续丢线"都会触发右转 →
葫芦圈**还没绕完就乱转** → "绕圈顺序也变了"。

> ⚠️ 这个冲突其实**我早就记过**（在 `app_config.h` 里写着"直角弯入口也是这个图案"），
> 但我把它当成"次要风险"，还用 `REQUIRE_ENTRY` 闸门以为能挡住 ——
> **实际上闸门挡不住：进葫芦圈之后闸门就一直是开的，直角弯在后面照样触发。**

---

## 三、教训（流程层面）

1. **一次只开一个开关** —— 我这次一次开了三个，结果分不清是谁的错，只能整体回退、白跑一趟。
2. **"我早就在注释里记过的风险"，不能当成"已经处理了"** —— 记下来 ≠ 解决了。
3. **判据有一点不唯一，就不能直接拿来驱动动作** —— `11000000` 有两个来源
   （葫芦圈出口 / 左直角弯出口），这种判据只能当**辅助**，不能单独触发动作。

---

## 四、下一步该怎么做出圈（思路，未实现）

必须找一个**直角弯不会满足**的条件。两个可选方向：

### 方向 A（简单、确定性高）：**只用"圈内持续丢线"当出圈判据**
```
条件： 已经进过葫芦圈(IG=1)  且  连续 >=3 拍全灭(持续丢线)
```
- **直角弯为什么不会满足**：直角弯在【圈外】，`IG=0` → 条件不成立 ✓
- **葫芦圈出口为什么满足**：绕完最后一个圆、线没了 → 全灭 ✓
- **代价**：完全不看图案，就靠"进过圈 + 丢线"
- ★这就是 `GOURD_EXIT_ON_LOST`，但**必须把图案判据一起关掉**
  （即 `GOURD_EXIT_LEFT_N` 那条不用）—— 我上次是两条都开，所以坏在图案那条上。

### 方向 B（需要实测）：**数"进圈图案出现过几次"**
```
直角弯： 11000000 只出现 1 次
葫芦圈： 几个圆之间有 3 个相切点 → IG 会亮好几轮
条件： 累计见过 >=2 次才算"真出圈"
```

**建议先试方向 A** —— 它只用"进过圈"和"丢线"两个已经验证过的信号，
不涉及任何图案匹配，最不容易再引入意外。
