## ⭐ 2026-09-08 工具习惯：VSCode 跑 STM32（固定流程 + 提醒）

> **⚠️ 固定提醒**：**每次打开新的 STM32 工程文件夹，都要发送 `/stm32-project-setup` 给内置 AI** —— 它会自动更新设置文档 / 配好 `.vscode` 调试（Cortex-Debug + OpenOCD + gdb）。这是让 AI 部署好的固定流程，别忘。

**完整流程**（新 STM32 工程）：
1. **CubeMX 生成**：Project Manager → Toolchain 选 **CMake** → 生成（自动带出 CMakeLists.txt / CMakePresets.json）。
2. **VSCode 打开**：直接打开含 CMakeLists.txt 那层文件夹。
3. **发 `/stm32-project-setup`** 给内置 AI → 自动配好 debug（executable=.elf、device=芯片、configFiles 按系列 stm32f1x/f4x.cfg）。
4. **日常开发**：编译 `Ctrl+Shift+B`、下载+调试 `F5`、停止 `Shift+F5`、生成 HEX → 终端→运行任务→「③ 编译并生成 HEX/BIN」；「⑤ 释放被占用的 ST-Link」任务一键清残留（治"连不上/GDB Server Quit"）。

**教训（写给自己）**：VSCode 跑 STM32 用的是 **OpenOCD + ST-Link**（嵌入式调试），跟"纯 C 程序在电脑跑"的 gdb 不是一回事，别混。报 `GDB Server Quit` 多半是 `.vscode` 没配好 / ST-Link 被占，跑「释放 ST-Link」任务或重配 launch.json。
