## 2. 版本与留档

### 2.1 ★今天新核实：hex 的 SHA-256 不能跨"重建"认版本

- 事实（实测）：当前 `MDK-ARM\test16\test16.hex` 与留档 `firmware\1021-1345\test16.hex` **大小都是 33220 字节**，
  逐字节比较**只差 3 个字节**（偏移 28356 / 28358 / 28359），差的正是固件里 `__TIME__` 烤进去的"`13:49:52`" vs "`13:45:xx`"。
- 结论：**同一份源码只要重新编译一次，hex 的 SHA-256 就一定变**（`__DATE__`/`__TIME__` 在固件里，开机横幅会打印 `built Oct 21 2026 13:49:52`）。
  ⇒ 留档表里的哈希只能用来认**"你手上这一份文件"**，不能用来认**"源码是哪版"**。
- **正确的认版方法**（按可靠度）：
  1. 串口开机横幅 `V`：看 `tag : 1016-Rxxx` + `built:` 时间（**前缀都一样时只能靠 built 时间**）；
  2. 镜像里搜 tag 串：`python -c "print(b'1016-R182' in open(r'MDK-ARM/test16/test16.axf','rb').read())"`（三版横幅同名 ⇒ 只能证明"是 R182 系"）；
  3. 掩掉时间戳区间再比哈希（要精确比对两份 hex 时用），或直接比 `Code` 大小。
- **实测佐证（2026-10-21 晚）**：车上横幅 `built: Oct 21 2026 13:49:50`；工作区 hex 里烤的 `__TIME__` = **`13:49:50`**，
  留档 `firmware\1021-1345` 那份 = **`13:44:31`**（其余逐字节相同）⇒ **⇒ 车上跑的就是工作区这份 = `fw-1021-1345` 源码**。
  即：`built:` 时间能和 hex 内的 `__TIME__` 对上，是可靠的身份证；SHA-256 不是。

## 4. ★★ 四条硬事实（2026-10-21 用卷尺 + 手转量出来的，别再猜）

测法（10 分钟，可复现）：卷尺 3m → **手推车走完（不开电机）** → 发 `Z` 清零 → 推 → 发 `O` 读 `OD/PATH/L/R`、发 `H` 读 `ENC1/ENC2`。
16 位定时器要按回绕折算：`Δ = ((end − base + 32768) & 0xFFFF) − 32768`。

1. **左轮 1 计数 = 531 µm**（三轮 ΔENC1 = 5625 / 5618 / 5700，散布 ±0.7%，很可重复）。代码里的 `491` 是按"轮径 66 ÷ PPR 422"推的 ⇒ **偏小 8.2%**。
2. **左轮一整圈 = 512 计数**（架空手转四次：512 / 505 / 509 / 521）⇒ `ENCODER_PPR=422` 是**从没实测过的推算值**。
   ⇒ `speed.c` 的 RPM 一直**报大 21%**（"57 档≈313RPM"真实约 258）⇒ 配 531µm/计数 ⇒ 轮子周长约 272mm ⇒ **轮径约 86.6mm**（设计书 66 也不对）⇒ 待卡尺确认。
3. **右编码器是坏的，而且它在污染里程**：手推 3m `ΔENC2 = −1 / 0 / 0`；跑车 `R=0`、右轮 `RPM≈5`；架空手转右轮一整圈 `ENC2` 纹丝不动。
   ⚠️ 里程公式是 `(|d_l| + |d_r|)/2` —— **绝对值累加**（9-23 为治"A/B 接反互相抵消"改的）。
   右通道不转只抖 ⇒ 抖动全被当路程加：**手推占 11.4%、跑车占 16.9%，且比例随震动变**。
   ⇒ **这就是"重量一换里程就漂、+50/+100 永远补不完"的机制**；它没法靠平移阈值修，因为它是随机项。
4. **现在 OD ≈ 真实距离的一半**：
   - `真距离 ≈ |L| × 1.0815`
   - `OD ≈ 真距离 × 0.515`（手推）/ `× 0.540`（跑车）；两者差 2.5 个百分点 = 右通道抖动
   - ⇒ **反算真实距离：`真 ≈ OD × 1.94`**（1/0.515）
   - ⇒ 那二十来个阈值（900/1500/3850/11176/12844/12994/16800/17155/17425、切点 783/1304/1806、BIAS 150、半宽 180/300/180）**全活在这套"半刻度"上**。
   - ⚠️ 今天试过"正经标定"（`ODOM_UM_PER_COUNT`→531/287 + 里程只用左轮 + 阈值换算），**已按他要求全部回退**。
     教训：动系数 = 动刻度 = 20 多个阈值要一起换算，且 `speed.c` 的 RPM 吃同一套假设 ⇒ **必须一次规划好，不能顺手改**。

### 5.2 血泪清单（别重犯）
1. **编译必须 0E0W 才给 hex**（`build.ps1` 严格模式，有警告就 throw；日志 `MDK-ARM\build-0929-R1.log`）。
2. **改"某条件下才生效"的逻辑前，先确认那条路会被执行到**：R157~R167 的起步改动**全白改** —— `line_follow.c` 里"持续丢线 ⇒ 原地旋转找线"的 `return` 在**误差整形链之前**（R168 才修）。
3. **"每趟一次性"的状态必须点名核对 `line_follow_gourd_rearm()` 清没清**：出口锁 `s_ex_done` 从没复位过 ⇒ **上电只有第 1 趟会右转**（R162 修的，曾污染 R157~R167 一整轮判断）。
4. **`#if` 开关别嵌套错**：关掉一个开关前先问"还有谁挂在这上面"。R160 关"盲走直"时把"斑马线不跟"一起关死了（R164 才拆开）；R160 的 `USE_BRANCH_EDGE=0` 会让 `gsp_dir_for()` 变"未被引用"⇒ **破 0E0W**，而且"里程定方向"整个功能也挂它上。
5. **改带多行注释的宏要整块替换**（踩过 3 次）；用 python 改文件时**中文引号会让脚本语法错**（用「」）。
6. **加诊断量之前先确认那行代码真的会跑**（犯过 3 次：字段加在只有 `H` 才打印的长行里，而当时 RX 不通 ⇒ 永远看不见）。"编译通过 + 烧录成功"不能保证"这行会执行"。
7. **`git revert` 会把那次提交里新增的 `firmware/xxxx/` 留档目录一起删掉** —— 今天差点丢，靠 `git checkout HEAD -- firmware/1021-1318` 救回。revert 前先确认留档还在。
8. **推算值必须标"未实测"**：`491`（轮径÷PPR）和 `422`（PPR）都是推的，用了半年没人核过 ⇒ 里程、转速两套刻度一起歪。以后常数要写来源 + 测法。
9. **`Z` 不清 `ENC1/ENC2` 寄存器**（只清 odom 累加器）⇒ 要原始计数对数得自己记前后值。
10. 文档卫生：作废标 ❌、归档不删、更新 `文档/文档索引与状态.md`。

| **`Z`** | 里程清零（当前位置当 0 点） | ⚠ 不清 `ENC1/ENC2` 寄存器 |
| `H` | 完整诊断行 `RAW=… ENC1=… ENC2=… WHO=70 IMU=1 GZ=…` | 看编码器原始计数 |
| `S <0~99>` / `P <x>` / `D <x>` / **`J <10~100>`** | 直道档 / KP / KD / 第一个弯后减速比例 | 都必须带数值；`J 100` = 不减速 |
| `R` / `XX` | 串口发车 / 急停（要两个 X） | 新板物理按键失效 ⇒ 一律用串口 |
| `TIK` / `END` | 里程打点（≤40 点）/ 吐点 + 锁车 + 停遥测 | 跑着车点；`END` 后发任意命令即恢复 |
| `M <左> <右>` / `T <1\|2> <速度>` | 架空测电机 | ⚠ 右编码器坏 ⇒ `T 2` 闭环会失控，务必架空 |
| `L <0~7>` | 直接点灯（bit0 = LED1） | 待机态才稳 |
| `B [ms]` | 蜂鸣 | **蜂鸣器没焊 ⇒ 听不见** |
| `Q` | 轨迹回放 | 已关（`USE_TRACE_DUMP_Q 0`） |

- **免回车**：命令攒了内容静默 **400ms** 自动提交（`USE_CMD_AUTOSUBMIT`），单个 `X` 例外。
- ⚠️ **手点 `TIK` 有系统性滞后**（反应 0.2~0.3s + 传输 + 未回车再加 400ms ⇒ 57 档约 **540mm**）⇒ **看"点与点之间的间距"最可靠**，绝对值要减偏置。
  可选改进（他没点头）：`TIK` 收到最后一个字母就立刻提交，能把残差压到 90~140mm。
