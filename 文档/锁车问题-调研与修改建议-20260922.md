## 一、症状（用户原话）

> "这车跑一段就停车跑一段就停车，特别是过复杂弯道的时候。"
> 后续补充：**"停了就是再怎么放都没反应"** —— 把车放回线上、挪动都没反应。

**关键点**：**不自动恢复** ↔ 这一句把范围缩到了很小。

## 二、已排除的可能（有代码依据）

| 候选 | 结论 | 依据 |
|---|---|---|
| 丢线兜底超时停车 | ❌ **排除** | `control/line_follow.c:153-168`：丢线超时确实会 `motor_stop()`，但**只要任一传感器重新看到线就立刻恢复**（`r.active != 0` → `lost_cycles = 0`）。与"再怎么放都没反应"矛盾 |
| `speed.c` 除零 | ❌ 排除 | `drivers/speed.c:35` 有 `if (dt == 0) dt = 1;` |
| 看门狗复位 | ❌ 排除 | 工程里没有启用 IWDG/WWDG |
| 电池/驱动过流保护 | ⚠️ **不是本次主因** | 那类保护**会自恢复**（负载一掉就恢复），与"没反应"矛盾。可作后续优化，但不是这个问题 |

## 三、结论：锁车 = `CAR_EMERGENCY`

**代码里唯一的"锁车"状态就是它，而且它没有任何自动退出路径。**

```c
/* fsm/car_fsm.c */
void car_fsm_request_start(void)
{
  if (state == CAR_IDLE || state == CAR_STOPPED) enter(CAR_COUNTDOWN);
}   /* ← 在 CAR_EMERGENCY 里调用它什么都不会发生 */
```

`CAR_EMERGENCY` 分支只做 `motor_stop()` + 三灯快闪，**没有回到其它状态的路径** →
**只能断电重上电**。`telemetry.c` 里急停命令的回复也写着"想再跑请重新上电"，即设计如此。

### 触发入口只有两个

| # | 入口 | 代码位置 |
|---|---|---|
| 1 | **长按启动键 1 秒** | `fsm/car_fsm.c` 的 `car_fsm_run()`：`if (key_take_long() && state != CAR_EMERGENCY) { car_fsm_emergency_stop(); return; }`（在 `#if !AUTO_START_ENABLE` 内；当前 `AUTO_START_ENABLE = 0`，即**按键是启用的**）|
| 2 | **串口收到 `X`** | `telemetry.c` 的 `X` 命令 → `car_fsm_emergency_stop()` |

### 两个入口都可能被"误触发"

1. **按键**：车在振动；按键被外壳/线材压住、或触点半接触 → `key.c` 消抖（稳定 10ms×3 = 30ms）后就认"按住" → 满 1s 即判长按。
   **另有一处隐患**：`key.c` 的 `key_init()` 里 `press_tick` 初值为 **0**，若**上电瞬间按键已处于按下（低电平）状态**，则 `HAL_GetTick() - 0 >= KEY_LONG_PRESS_MS(1000)` 会在**开机第一秒内**直接报一次长按 → 一起步就急停。
2. **串口**：`文档/代码交接说明-20260921.md` 的"已知问题"写着 **"串口 RX 收不到 → 待修"**。若 PA10 实际处于**悬空**状态，电机 EMI 很容易灌入凑出 `X` + `\r` 的组合 → 永久急停锁车。

## 四、判别流程（5 步，不用改代码，现场就能定案）

| 步骤 | 看什么 | 结论 |
|---|---|---|
| 1 | **三灯**：慢闪(250ms 节拍) = `CAR_STOPPED`；**快闪(150ms 节拍) = `CAR_EMERGENCY`**；第 3 灯常亮 = `CAR_RUN`；全灭 = `CAR_IDLE` | 快闪 → 就是急停锁车 |
| 2 | **串口还在不在打印** | 还在打 = MCU 活着；不打 = MCU 死机/复位（转 4）|
| 3 | 读遥测里的 **`ST=`**：0待机/1读秒/2运行/**3到站**/**4急停** | **`ST=4` = 定案（急停锁车）** |
| 4 | 串口日志里搜 **`OK EMERGENCY-STOP`** | 出现 = 是**串口 `X` 噪声**触发的（决定性证据）|
| 5 | 按一下启动键 / 断电重上电 | 按了没反应 + 重新上电恢复 = 确认 EMERGENCY 锁车 |

## 五、修改建议（按优先级）

### P0-1 ★ 给急停加"原因"并留出口
- **原因**：现在两个入口共用一条路，出了事分不清是按键还是串口——这次就卡在这。比赛现场"锁死不能动"比"误停"更致命。
- **建议**：
  1. 在 `car_fsm.c` 里加一个 `emg_cause` 字段（0=无 1=按键 2=串口 3=其它），`car_fsm_emergency_stop()` 增加一个入参或在调用点分别设置；
  2. 进急停时通过 `telemetry` 打一行带原因的日志（如 `STOP by KEY` / `STOP by X`）；
  3. **给 EMERGENCY 加退出路径**：**长按 2 秒**回 `CAR_IDLE`（推荐），或可选"N 秒后自动回 IDLE"。

### P0-2 ★ 修 `key.c` 上电即长按的隐患
- `key_init()` 的 `press_tick` 初值 0 → 上电时按键若已是低电平，开机 1s 内直接报长按。
- **建议**：`key_init()` 补 `press_tick = HAL_GetTick();`；并考虑**忽略开机前 300~500ms 内的按键电平**（防上电抖动）。

### P0-3 ★ 串口 `X` 加二次确认 + 治 PA10 悬空
- 一个能"远程把车锁死"的命令，误触发代价太高。
- **建议**：`X` 改成需连发两次（如 `XX`）或加参数（`X 1`）；同时**把 PA10 的悬空问题解决**（空脚配置上拉或下拉；`gpio.c`/CubeMX 里改），并在接收侧做白名单校验（只接受已知命令字母 + 长度上限，现在已有 32 字节上限，可再加首字母白名单）。

### P1-1 确认 RX 是否真的坏
- README 把串口命令表当可用功能写，交接说明写"RX 收不到"。**这两者矛盾**，请先确认现状（发 `V` 看有无回）。
- 若 RX 确实坏：**在线调参全废**（`P/S/D` 只能改宏重烧），优先级其实很高。

### P1-2 复现与回归测试（改完必须做）
1. **复现急停**：架空车，长按启动键 1s → 应进 EMERGENCY（三灯快闪、串口 `ST=4`、日志出现原因行）；
2. **验证新出口**：长按 2s → 应回 IDLE，且能再次按键启动；
3. **验证区分原因**：串口发 `X` → 日志应显示"by X"；
4. **回归丢线停车**：架空 + 挡住 8 路传感器 → 按设计约 1.5s（`LOST_MAX_CYCLES 150` × 10ms）后停车，**且此时把纸拿开、让传感器重见线，车应立即恢复**（这条是既有行为，别改坏）；
5. **回归按键启动**：短按 → 3s 读秒 → 起跑，正常。

## 六、别动的东西（边界）

- `app_config.h` 的 **`LINE_ACTIVE_LEVEL`**（本车 8 路模块"白线输出高"→ `GPIO_PIN_SET`，实测定的）、**`LINE_CHANNEL_TABLE` 引脚顺序**（左→右 `-7…+7`）

- 改完请按项目规矩**更新 `FW_TAG`**（格式 `MMDD-HHMM`），方便用串口确认烧没烧

## 七、给接手者的"现场读日志"速查

```
FW:0922-0940 IR:10110000 RPM1=210 RPM2=205 KP=3.0 SP=70 ST=2 GZ=0 GW=0 SB=0
```
- `IR:` 8 位 = 从左到右 8 路（**第 1 个字符 = 最左那路**，`line_sensor.c:23` 用 `1u<<i`，i 跟通道表）
- `ST:` 0待机 / 1读秒 / 2运行 / 3到站 / 4急停
- `GZ` 偏航率(°/s，IMU)｜`GW` 葫芦相切点计数（跑完整圈应回到 3→0）｜`SB` 直线提速中标志
- 待机 500ms 一行；读秒/运行中 **50ms** 一行
- 串口命令：`P<KP>` `D<KD>` `S<速度>` `T<1|2><pwm>` `M<L><R>` `L<0~7>` `B[ms]` `R`(启动) `V`(版本) `H`(诊断) `X`(急停)
