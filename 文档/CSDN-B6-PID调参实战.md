## 二、循迹控制的基本框架

循迹小车 = 传感器（"看"线在哪里）→ 控制器（算该往哪修）→ 电机（执行转向）。拆开就三件事：

```
5路红外传感器 → 加权误差 e → PD控制器 → 差速(左轮+Δ, 右轮-Δ) → 车转向追线
```

**核心变量：误差 e**
- e = 0：车正压在线中间 ✅
- e < 0：线在左边（偏左）
- e > 0：线在右边（偏右）

误差算得准不准，决定控制好不好。我的 5 路传感器从左到右加权 `{-2, -1, 0, 1, 2}`，哪个传感器压线就把它的权重加进误差：

```c
/* 读取5路循迹传感器，返回加权误差: 偏左为负，偏右为正，居中为0 */
static int8_t read_sensors(void)
{
  GPIO_TypeDef* ports[5]  = {IR_L_GPIO_Port, IR_LM_GPIO_Port, IR_C_GPIO_Port, IR_RM_GPIO_Port, IR_R_GPIO_Port};
  const uint16_t     pins[5]   = {IR_L_Pin, IR_LM_Pin, IR_C_Pin, IR_RM_Pin, IR_R_Pin};
  const int8_t       weights[5] = {-2, -1, 0, 1, 2};   /* 左->右加权 */
  int8_t error = 0;
  uint8_t active = 0;

  for (uint8_t i = 0; i < 5; i++)
  {
    if (HAL_GPIO_ReadPin(ports[i], pins[i]) == LINE_ACTIVE_LEVEL)
    {
      error += weights[i];
      active++;
    }
  }
  /* 丢线处理：见后面"丢线旋转找线"章节 */
  if (active == 0)
  {
    lost_cycles++;
    if (lost_cycles <= LOST_SPIN_DELAY) {
      line_lost = 0;
      error = last_error * 2;          /* 短暂丢线: 沿上次方向加强修正 */
    } else {
      line_lost = 1;                   /* 持续丢线: 交给原地旋转找线 */
      error = 0;
    }
  } else {
    last_error = error;
    lost_cycles = 0;
    line_lost = 0;
  }
  return error;
}
```

> **踩坑 1：传感器极性（LINE_ACTIVE_LEVEL）**。我的模块是"白板触发"型：白板亮灯/DO输出低，黑线熄灯/DO输出高。所以黑线=高电平=检测到，要设 `LINE_ACTIVE_LEVEL = GPIO_PIN_SET`。**不同模块极性可能相反，一定要实测**——对着黑线白纸各看一次串口 IR 值，反了就改这一个宏。我一开始用反了，车把白板当线，满场乱跑。

**IR 状态表**（黑线=1，白板=0，从左到右 5 位）：
| 状态 | IR |
|---|---|
| 悬空/全黑 | 11111 |
| 偏左 | 01000 / 01100 |
| 居中 | 00100 |
| 偏右 | 00010 / 00110 |
| 大左偏 | 11100 / 10100 |
| 大右偏 | 00101 / 00111 |

## 三、P 控制：让车"转向线"

最简单的控制器：修正量 = KP × 误差。

```c
int16_t corr = kp_x10 * e / 10;   /* 误差 -4..4 → 修正量 */
change1(base_speed + corr);        /* 电机1 = 左轮 */
change2(base_speed - corr);        /* 电机2 = 右轮 */
```

线偏右（e>0）→ 左轮加速、右轮减速 → 车右转追线 ✅

> **踩坑 2：转向方向反了（疯狂左转）**。我一开始写的是 `change1(base - corr)`，物理上电机1驱动左轮，线偏右时左轮减速右轮加速 = 车左转 = 越转越偏 → **疯狂左转**。这个 bug 我调了很久才发现，因为"代码注释写的是电机1=左轮"，但接线实际是电机1=左轮……**方向对不对，别信注释，架空车轮 T 命令实测**（发 `T 1 40` 看哪个轮转、往哪转）。

**KP 实测记录**（SP=40，其他参数不变）：

| KP | 现象 |
|---|---|
| 10 | 直线蛇形严重（画龙） |
| 8 | **直线可接受 + 弯道跟得上（甜点）** |
| 4 | 直线稳，但弯道转不过来（冲线） |

结论：KP 太小 → 跟不上弯；KP 太大 → 直线过冲蛇形。**先调 P 到"直线勉强不画龙 + 弯道勉强能过"，再上 D 项**。

## 四、D 项：直线蛇形的解药

蛇形的本质是**修正过冲**：车偏一点 → P 猛修 → 修过头 → 偏另一边 → 再猛修……无限循环。P 控制看不到"车正在以多快的速度偏"，所以刹不住。

**D 项（微分）= 按误差变化速度给阻尼**：误差正在增大（车在偏离）→ 阻尼对抗；误差正在减小（车在回正）→ 阻尼让它别冲过头。

```c
int16_t d_term = (int16_t)(e - last_e);               /* 误差变化率 */
int16_t corr = kp_x10 * e / 10 + kd_x10 * d_term / 10; /* P项 + D项 */
last_e = e;
```

**KD 实测**：KD=30（配合 KP=8、20ms 控制周期），直线从"画龙"直接变"走直"——**这是整个调参过程里最爽的一次质变**。

> **踩坑 3：控制周期不是越快越好**。我把控制周期从 20ms 改到 10ms 想"响应更快"，结果车**一步一甩头**。原因：传感器只有 5 档离散值（-4..+4），10ms 采样时误差跳变更频繁，D 项把离散跳变当"剧烈变化"放大 → 疯狂抖动。**回退 20ms 后完美**。数字传感器 + D 项，控制周期别太短。

## 五、丢线处理：比 PID 更重要的救场

直角弯、锐角弯时，线会瞬间从传感器视野里消失（00000）。P 控制这时候是瞎的，处理不好就是冲出赛道。

我的方案是**两段式丢线处理**：

1. **短暂丢线（前 2 个控制周期）**：沿上次误差方向加强修正 `error = last_error * 2`——应对传感器瞬间没压上
2. **持续丢线**：**原地旋转找线**——朝上次偏差的方向原地打转（一前一后），直到重新看到线

```c
/* 持续丢线: 原地旋转找线（先朝上次偏差方向转） */
if (line_lost)
{
  if (lost_cycles > LOST_MAX_CYCLES) {
    change1(0); change2(0);            /* 找线超时(1.5s): 停车防跑飞 */
  } else if (last_error >= 0) {
    change1(LOST_SPIN_SPEED);          /* 线之前在右 → 右转找线 */
    change2(-LOST_SPIN_SPEED);
  } else {
    change1(-LOST_SPIN_SPEED);         /* 线之前在左 → 左转找线 */
    change2(LOST_SPIN_SPEED);
  }
  return;
}
```

**效果**：直角弯从"冲出去回不来"变成"原地转一下，找到线继续跑"。我的赛道 7 个 360° 弯，靠它只错 1 个极小弯。

## 六、I 项：我帮你踩过的坑

教科书说 PID 三项俱全，但**循迹车急弯多，我实测 I 项弊大于利**：

- I 项治"恒定偏角"（车一直偏同一侧拉不回来），适合长直线
- 我试 KI=0.2：误差在弯道里持续偏一侧 → 积分疯涨 → 丢线时积分没复位 → **车原地转圈**
- 结论：**急弯赛道别上 I 项**。除非你加"抗积分饱和 + 丢线时积分清零"，否则纯 PD 更稳

## 七、完整 line_follow 代码（PD + 丢线旋转）

```c
/* 循迹差速控制: 每20ms调用一次 */
static void line_follow(int16_t base_speed)
{
  int8_t e = read_sensors();

  /* 持续丢线: 原地旋转找线 */
  if (line_lost)
  {
    if (lost_cycles > LOST_MAX_CYCLES) {
      change1(0); change2(0);
    } else if (last_error >= 0) {
      change1(LOST_SPIN_SPEED);
      change2(-LOST_SPIN_SPEED);
    } else {
      change1(-LOST_SPIN_SPEED);
      change2(LOST_SPIN_SPEED);
    }
    return;
  }

  int16_t d_term = (int16_t)(e - last_e);
  int16_t corr = kp_x10 * e / 10 + kd_x10 * d_term / 10;  /* PD */
  last_e = e;

  if (corr > 99)  corr = 99;
  if (corr < -99) corr = -99;

  int16_t m1 = base_speed + corr;   /* 电机1 = 左轮 */
  int16_t m2 = base_speed - corr;   /* 电机2 = 右轮 */
  if (m1 > 99) m1 = 99;  if (m1 < -99) m1 = -99;
  if (m2 > 99) m2 = 99;  if (m2 < -99) m2 = -99;
  change1(m1);
  change2(m2);
}
```

**参数默认值（写死在固件里）**：`KP=8, KD=30, SP=40`——断电重启直接是最优配置，比赛现场不用调。

## 八、调参方法论总结（我的整定顺序）

1. **先验证传感器**：串口看 IR，黑=1 白=0，5 路一致，左右不反（这一步错了后面全白调）
2. **先验证转向方向**：架空车轮，单电机测试，确认"线偏右→车右转"
3. **先 P 后 D**：P 调到"直线勉强不画龙 + 弯道勉强能过"，再上 D 项压蛇形
4. **D 项从中间值开始**：我 KD=30（配合 KP=8）；蛇形残留→加，弯道迟钝→减
5. **I 项急弯赛道直接跳过**
6. **控制周期 20ms 别乱改**
7. **最后调速度**：S 从 40 起步，稳了再加；冲到 S=50 直角弯开始冲线，就定格在 40

**真实数据**：S=40 时 1.9m 直线 3.56s（约 0.53 m/s），全程赛道稳定跑圈。

## 九、附录：其他真实踩坑（每个都能省你几小时）

1. **串口只发不收**：USART1 的 RX 引脚（PA10）被配成了推挽输出（AF_PP），输入信号被顶住。改成输入模式就好了。**CubeMX 重新生成代码会把这个修复冲掉，注意**
2. **霍尔测速恒为 0**：EXTI 回调里用 `==` 判断 `GPIO_PIN_11|GPIO_PIN_12` 的合并掩码，永远不相等。改成**按位与** `&`，且中断入口拆成单脚调用
3. **电机时转时不转**：电机输出线虚焊，扯线测试才暴露。**焊完一定要做拉力测试**
4. **电机响但轮子不动**：锂电池没电了（电压不足）。**调试/比赛前先确认电池满电**
5. **PCB 打样**：封装尺寸务必对照实物核对（我的驱动板就因封装问题只能外接）；电源线加粗（VM≥40mil）；信号线远离晶振和电机线
